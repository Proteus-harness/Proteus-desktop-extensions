# Визуализации

Самостоятельный пакет клиента: завершённые блоки ответа с языком `json-render`
показывает нативными виджетами, `svg` — цветным нативным изображением.
Установка и выключение — обычные **Settings → Extensions**. Пакет использует
публичную поверхность `content`; клиент не знает его каталог и имя.

Исходный текст остаётся у блока. Пока блок не завершён, пакет выключен,
не установлен, не поддерживает язык или вернул ошибку, клиент показывает
обычный код. Копирование исходника не зависит от удачного preview.

## Формат json-render

Один JSON-объект с `type` в `snake_case`. Имена полей совпадают с публичными
виджетами клиента. Неизвестные типы и поля дают ошибку всего блока; обрезанных
или частично работающих форм нет. Каталог содержит только представление данных:

| type | Обязательные поля | Необязательные поля |
|---|---|---|
| `stack` | — | `children`, `direction`: `column`/`row`, `gap`: `none`/`small`/`medium`/`large` |
| `card` | — | `title`, `children` |
| `text` | `text`: строка | `tone`, `size`: `small`/`normal`/`large`, `single_line`, `mono` |
| `metric` | `label`, `value`: строки | `detail`, `tone` |
| `table` | `columns`: строки, `rows`: массивы строк | — |
| `bar_chart` | `bars`: `[{label, value, tone?}]` | `unit` |
| `tabs` | `tabs`: `[{label, count?, children?}]` | — |
| `svg` | `source`: строка, `width`, `height`: числа | — |

`children` — массив таких же объектов. Значения столбиков конечны и неотрицательны;
в строке таблицы столько же ячеек, сколько заголовков. `count` — неотрицательное
целое. `tone`: `default`, `muted`, `accent`, `success`, `warning`, `danger`
или `#rrggbb`. По умолчанию текст переносится; `single_line: true` включает
общую подпись с затуханием при нехватке ширины.

Tabs переключаются локально, без action и обращения к серверу. Кнопки,
запросы инструментов, `action`, обработчики, URL-поля, HTML и JS в каталоге
отсутствуют. Пределы одного исходника: 256 КиБ, глубина 24, 2000 виджетов.
Некорректные данные остаются доступны как исходный код с ошибкой preview.

## SVG

В fence `svg` передаётся полноценный SVG с собственным `viewBox` и `xmlns`.
Пакет задаёт область 640×360 логических пикселей; общий рендерер сохраняет
изображение как нативный цветной SVG. Для другого размера используйте
`{"type":"svg","source":"<svg ...>...</svg>","width":480,"height":240}`
в `json-render`; допустимый размер — 1…4096 по каждой оси.

SVG проверяет общий примитив клиента: корректный XML, корень `svg`, ссылки
только на локальные `#fragment`; `script`, `foreignObject` и внешние ресурсы
не принимаются. Пакет не читает указанные в SVG пути и не открывает браузер.

## Необязательный skill

`skills/visualize/SKILL.md` входит в ZIP/portable рядом с этим README, но
установка расширения **не включает инструкции агента автоматически**.
Без skill пакет работает с любым уже полученным корректным блоком.

Чтобы агент сам выбирал визуализацию, скопируйте папку `skills/visualize`
из установленного пакета в `<ваш проект>/.proteus/skills/visualize`.
После следующего чтения skills проверьте `visualize` в **Settings → Skills**;
его можно выключить независимо от расширения. Другой вариант — поместить
эту папку в свой git-каталог skills и установить через **Settings → Каталог**.
Пакет не меняет профиль, системный prompt и каталоги пользователя.

`examples/rich-content.md` — синтетический ответ для ручной проверки:
таблица, метрики, Tabs, график, SVG и случаи возврата к исходному коду.
