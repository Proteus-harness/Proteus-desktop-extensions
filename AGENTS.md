# Расширения Proteus Desktop

В `packages/<id>/` лежат Rust-бинарник и манифест каждого расширения.
Общий SDK — крейт `proteus-extension` в `sdk/`. Штатные и пользовательские
пакеты работают через один [публичный протокол](PROTOCOL.md).

## Изменение расширения

Логику пакета держите в самом расширении. Для нового нативного виджета
обновите схему Desktop и её потребителей вместе. Для панелей и клавиатуры
ориентируйтесь на Zed и [правила интерфейса Desktop](https://github.com/Proteus-harness/Proteus-desktop/blob/main/DESIGN.md).

При смене сессии отбрасывайте запоздавшие ответы. Для обновлений рендерера
сверяйтесь с [протоколом контента](PROTOCOL.md#контент-ответа-в-чате).
Учёт байтов, пределы кэша и проверка расхода памяти описаны в [руководстве по ОЗУ](https://github.com/Proteus-harness/Proteus-core/blob/main/docs/development/memory.md).

Пакеты выпускаются под GPL-3.0-or-later, SDK — под Apache-2.0.
При переносе кода из Zed указывайте исходный файл. В SDK используйте только
Apache-лицензированный код Zed. См. [лицензии пакетов](README.md#лицензия).

## Проверка и поставка

- Одно расширение — `cargo test --locked -p extension-ID`. Для общего SDK — `cargo test --workspace`.
- Для проверки в checkout соберите пакет командой `python3 package.py --package ID --dev`.
  Для установки через менеджер соберите ZIP командой `python3 package.py --package ID`.
- Изменение протокола проверьте с Desktop в нативном окне на синтетических данных.
  Токены сервера и содержимое реальных сессий не записывайте в логи.
- При правке упаковщика проверьте затронутую операцию и установку готового пакета.

Проверенную правку расширения оформляйте отдельным коммитом. Для обновления
штатного набора в portable соберите компонент `extensions`, а при изменении
общего протокола — также `desktop`. См. [выбор компонентов](https://github.com/Proteus-harness/Proteus-desktop/blob/main/BUILDING.md#выбор-компонентов).
