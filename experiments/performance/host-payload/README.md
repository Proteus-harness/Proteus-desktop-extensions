# Передача готового дерева без транзитных копий

SDK сохраняет последний успешный root для показа ошибки поверх него. Раньше
`json!` глубоко копировал этот root в исходящее сообщение. Теперь envelope
временно владеет исходным root, отправляет его по ссылке и возвращает ту же
allocation в `shown`. Поля, порядок JSON, fallback и освобождение при close
сохранены. Уже принадлежащие SDK state/entries также переносятся из входного
сообщения. Markdown сохраняет независимость возвращаемого дерева от cache,
но переносит уже созданный массив children в root без ещё одного clone.

## Повторение

Используйте одинаковые обычные release-профили. Сохраните готовые executables
до изменения кода; runner ничего не собирает. Кэши Cargo/ОС не очищайте.

```sh
cargo build --locked --release -p proteus-extension --example host_cost
cargo build --locked --release -p extension-markdown-render --bin markdown-render
python3 experiments/performance/host-payload/bench.py \
  --binary /absolute/ready/host_cost \
  --output "$PWD/target/verification/host-cost-new"
```

`sdk/examples/host_cost.rs` вызывает настоящие публичные методы Host и
сериализует настоящий stdout. Синтетическое дерево: 512 текстовых виджетов
по 4096 ASCII bytes. Вход строится до начала измерения; его создание и
удерживаемое предыдущее дерево исключены из дополнительных выделений show.
Счётчик делегирует System allocator, считает запрошенные bytes и allocations,
а также прирост одновременно живых запрошенных bytes. Realloc считается
новым запросом своего полного размера. Это не RSS/PSS и не heap profiler.
Первый show со служебной инициализацией записан отдельно. Медиана обновлений —
10 последующих show, три отдельных процесса для каждого метода. Вывод
потоково хешируется без удержания большого JSON в драйвере. Wall time включает
инструментирование, сериализацию и чтение pipe; это не latency полного UI.

Для проверки самого Markdown используется существующий
[стенд рендереров](../../native-renderers/README.md): готовый пакет, один
синтетический документ с 800 заголовками/абзацами/код-блоками, 197380 UTF-8
bytes, 20 циклов с двумя сессиями, cache hit, изменением source/theme,
закрытием обоих views и contexts. `--language markdown --root-type any
--cycles 20 --repeats 3 --idle 0.1`. GUI, Core, модели и сборки одновременно
с замером не запускаются. Сгенерированный исходник остаётся в raw output.
Корпус воспроизводится `python3 experiments/performance/host-payload/fixture.py
--output /absolute/new/markdown.md`. Вариант «после» включает совместный эффект
изменений SDK и Markdown; их отдельный вклад в latency здесь не измеряется.

## Результат 2 ноября 2026

Точные hashes и raw report paths — [evidence.json](evidence.json).

| Операция show, медиана | До | После |
|---|---:|---:|
| Выделено, keys | 2330527 bytes | 1284 bytes |
| Число выделений, keys | 4117 | 18 |
| Дополнительно живые запрошенные bytes, keys | 2330154 | 912 |
| Выделено, title | 2330537 bytes | 1290 bytes |
| Число выделений, title | 4118 | 18 |

Оба метода передают побайтно одинаковый wire до/после. Снимки и splice
проверяются на сохранение исходных String/Vec allocations, допустимые формы
входа, stale updates и порядок callbacks.

Markdown: медиана 60 повторных рендеров **5,40 → 3,59 мс**, CPU процесса за
сценарий **3,54 → 3,14 с**. Roots всех сравниваемых first/cache/source/theme/
second-session ответов идентичны. Sampled peak PSS **28864 → 28736 КиБ**;
последние четыре закрытых состояния после правки — 28736 КиБ. Это близкие
значения, а не доказанное уменьшение resident ОЗУ. Короткая серия из трёх
циклов давала противоположный порядок PSS; это и стало причиной длинной
проверки. Освобождённые Values не обязаны немедленно вернуть страницы ОС.
После EOF оба дерева процессов пусты. Выигрыш относится к стоимости передачи
и повторной подготовки дерева, не к памяти всего приложения или отсутствию
долговременных утечек.
