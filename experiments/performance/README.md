# Память расширений: 1 ноября 2026

Сравнение ниже относится к отдельным готовым процессам, не к полной памяти
Proteus. Все входы синтетические; model/API calls отсутствуют. Прогоны идут
последовательно без GUI, сборок и других наших бенчмарков. Общий sampler Core
считает PSS/RSS/SwapPss и sampled peaks; драйвер не хранит большие roots.

Числа, hashes и ссылки на raw reports: [evidence-20261101.json](evidence-20261101.json).
Стенды остаются в проекте: [Git](git-cache/README.md),
[проекция](session-projection/README.md), [рендереры](../native-renderers/README.md).

| Сценарий | До, PSS МиБ | После, PSS МиБ |
|---|---:|---:|
| 48 разных Git preview закрыты, badge жив | 41,29 | 12,49 |
| Пик того же Git-процесса | 41,29 | 12,96 |
| Model + Mode + Context, 8 результатов тулов по 512 КиБ | 15,66 | 3,37 |

Git удерживал все просмотренные commit/file diff до исчезновения сессии.
Общий LRU ограничен 16 записями / 8 МиБ encoded JSON с ключами, full/short
aliases удаляются вместе. Большой ответ показывается без удержания.
Последние три точки after: 12,24 / 12,49 / 12,49 МиБ. После освобождения всех
владельцев повторное открытие действительно идёт в HTTP у обоих вариантов.
Различие PSS после close (3,77 против 8,11 МиБ) не равно различию живых Values:
allocator может удерживать уже освобождённые страницы. Raw directories с
суффиксом `20261103` — исторические имена worker, не дата этого отчёта.
Оба Git-варианта использовали одинаковый Process helper из `1fa4351`; после
замеров в него добавлены generic roots/cycles и редактирование trace. В JSON
сохранены исходные hashes: текущий helper не выдаётся за использованный в Git.

Три компактных виджета не читают entries. Новый `session_entries: false`
сохраняет state/config и исключает истории тулов до копирования на отдельного
подписчика и кодирования. На одинаковых бинарниках один synthetic snapshot
уменьшился с 4 195 666 до 580 bytes. Обновление state меняло каждый badge,
после EOF процессов не оставалось. Это стоимость приёмников: Desktop всё ещё
создаёт одну общую Entries-проекцию для события; её lazy construction не проверена.

## Повторное открытие рендереров

По 20 циклов: два context/session, первый render, cache hit, новый source,
новая тема, второй вид; закрытие первого view/context, проверка живого sibling,
закрытие последнего view/context. После EOF дерево каждого процесса пустое.
В native Mermaid/LaTeX не запускался JavaScript. Markdown headless возвращает
вложенные content nodes; стоимость смонтированных дочерних рендереров сюда не входит.

| Рендерер | PSS после первого закрытия, КиБ | После 20-го, КиБ | Пик, КиБ |
|---|---:|---:|---:|
| Mermaid Rust | 6951 | 6991 | 6991 |
| LaTeX | 2992 | 3088 | 3088 |
| Markdown | 3391 | 3995 | 3995 |
| JSON | 1211 | 1243 | 1243 |

В этом коротком сценарии не воспроизведён рост на размер каждого закрытого
документа. Markdown вышел на стабильные 3995 КиБ; небольшое увеличение других
процессов не доказывает ни утечку, ни её отсутствие. Это не heap-profiler и
не проверка многочасового streaming/slow-consumer сценария. Ограничение cache
в тестах и проверка последнего владельца сильнее одного значения RSS.
