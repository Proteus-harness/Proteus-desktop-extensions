# Mermaid На Rust: Эксперимент

Отдельное процессное расширение протокола 4 для fenced-блоков `mermaid`.
Готовая библиотека [mermaid-rs-renderer 0.3.1](https://github.com/1jehuang/mermaid-rs-renderer)
выполняет разбор, компоновку, измерение текста и выпуск SVG. Наш адаптер
передаёт реальную тему клиента и возвращает публичный `ui::svg`; GPUI/resvg
рисует его нативно. Node.js, JavaScript, браузер, WebView, дочерние процессы,
загрузка ресурсов по сети во время рендера не нужны. Cargo-зависимость
закреплена как `=0.3.1`, её CLI и PNG features выключены.
В экспериментальном workspace к этой версии применяется небольшой локальный
патч `Theme.node_corner_radius`; источник — проверенный архив crates.io.
Ветвление из ромба использует backport исправления автора
[`3e431ecb`](https://github.com/1jehuang/mermaid-rs-renderer/commit/3e431ecb6c8f98bfeb47fc5af38db60b4c9b1b5a),
адаптированный для четырёх направлений схемы. Parser и размещение узлов
остаются upstream; готовый маршрутизатор выбирает точки подключения,
строит линии и размещает подписи. Локальный патч также меняет углы фигур
и обрезает конечные участки через готовую геометрию `kurbo 0.11.3`.

Это альтернативный пакет `mermaid-rust-render` в отдельном экспериментальном
workspace. Он не входит в стандартную поставку и не заменяет `mermaid-render`
автоматически. При ручной установке выбирайте один Mermaid renderer, чтобы
два пакета не конкурировали за один язык.

Из корня репозитория:

```bash
export CARGO_TARGET_DIR="$PWD/target"
export CARGO_BUILD_JOBS=2
cargo test --manifest-path experiments/native-renderers/Cargo.toml --locked -p extension-mermaid-rust-render
python3 experiments/native-renderers/package.py --package mermaid-rust-render
```

Подготовка остальных пакетов, изолированный запуск и постоянный benchmark —
в [README эксперимента](../../README.md).

## Совместимость И Пределы

Синтаксис и компоновка определяются библиотекой, не полной реализацией
mermaid.js и не Pele. Проверяемый локальный корпус содержит flowchart,
sequence, class, кириллицу, подписи рёбер и `style`; одинаковая картинка
с Pele не гарантируется. Другие upstream-типы доступны экспериментально,
без заявления о полной совместимости. Указания `init` о теме не заменяют
палитру клиента; `style` отдельных узлов интерпретирует библиотека.
Некорректный/неподдерживаемый ввод даёт `content_error`, оригинальный
исходник остаётся доступен, если upstream действительно сообщает ошибку.
Его `parse_mermaid_strict` проверяет только отдельные случаи: неизвестный
заголовок, незакрытый `subgraph`, некоторые неверные стрелки и директивы.
Например, `flowchart TD` с `A[unfinished` библиотека принимает как буквальный
идентификатор узла и рисует его вместе с незакрытой скобкой. Это известное
ограничение эксперимента, закреплённое отдельной fixture и тестом; собственной
реализации Mermaid-validator в адаптере нет.
Ссылки, изображения, `foreignObject` и скрипты
не принимаются нативной границей адаптера.

Исходник ограничен 50 000 байт UTF-8; разобранный граф — 500 узлами и
500 рёбрами до компоновки. SVG — 1 МиБ. Размер вписывается в 640 × 4096
логических пикселей с сохранением пропорций; XML и размеры результата
проверяет готовый `roxmltree`, не строковый разбор тегов.
Каждая сторона viewport не меньше 1 пикселя по контракту клиента: у особо
широких/высоких диаграмм естественный `viewBox` сохраняется, а SVG вписывается
в этот viewport без растяжения содержимого.

## Скругления Приложения

В «Настройки → Расширения → Mermaid на Rust» есть выбор:

- **Наследовать из приложения** — режим по умолчанию; используется
  `Content.context.theme.radius_lg` в логических пикселях (0–256).
- **Свой радиус** — независимое значение для Mermaid, изначально 8 px,
  допустимо 0–64 px, включая дробные значения. Подтвердите кнопкой
  «Применить» или Enter. 0 делает углы острыми; например, 4–8 px даёт
  менее выраженное скругление.

Свой радиус меняет только палитру запроса этого расширения и не изменяет
настройки приложения. Для старого клиента, не передающего необязательный
токен `radius_lg`, наследование использует 16 px.
Перед рендером радиус компенсируется на масштаб вписывания SVG: на большой
диаграмме он сохраняет размер в пикселях, насколько позволяют размеры узла.
Upstream ограничивает углы длиной стороны; поэтому маленький узел физически
не может вместить большой радиус. Все четыре угла ромба ограничиваются
одинаково, в том числе при 32 px и выше.

Радиус распространяется на Rectangle, ActorBox, RoundRect и Diamond.
Заливка ромба — замкнутый path с четырьмя quadratic-кривыми существующего
`rounded_polyline_path`, а не имитация через `stroke-linejoin`. Новых
алгоритмов геометрии и постобработки SVG нет; для пересечения контуров
используется `kurbo 0.11.3`. Другие фигуры сохраняют
свой upstream-вид. Непереданный `Theme.node_corner_radius` в самой библиотеке
сохраняет её прежние значения, поэтому расширение API не меняет defaults.

Токен радиуса общий с приложением; точная форма кривой отличается:
SVG использует upstream quadratic helper, приложение — WGPU quartic
superellipse. Pixel-identical контур не обещается. Радиус не меняет
размещение узлов. Отдельный backport ветвления выбирает симметричные выходы
из ромба и входы около середины обращённой стороны конечных блоков,
чтобы оптимизатор не сокращал ветки за счёт смещения к углам. Обычные
цепочки и обратные рёбра цикла также используют центр выбранной стороны,
когда это единственное подключение на ней. Несколько подключений к одной
стороне, self-loop и границы subgraph сохраняют разнесённые upstream-порты;
обратное ребро сохраняет выбранную внешнюю полосу маршрута. Это правило
работает при assignment и refinement до маршрутизации, не переставляет
готовые SVG-линии поверх препятствий. Точный цикл «Кофе → Идея → Код →
Работает? → Кофе/Релиз» проверяется в LR/RL/TB/BT, включая положение
подписей, нормали входов/выходов, контакт с округлённым контуром и SVG bounds.
Концы flowchart-стрелок пересекаются с фактической скруглённой границей
через готовый `kurbo 0.11.3`: для прямоугольников используется RoundedRect,
для ромба — тот же quadratic path, который рисуется в SVG. Устаревший
конечный изгиб внутри старого прямоугольного контура удаляется, если он
уводит наконечник мимо фактической границы. Линия и оба наконечника
используют один окончательный набор точек без дубликатов. Тесты проверяют
0/4/8/16/32/64, симметрию, замкнутую заливку, стык с контуром, направление
наконечников, сохранение внутреннего маршрута и крайние пропорции.

Страница использует существующие публичные `page`, `select`, `input` и
`button`, а не отдельную схему конфигурации или новый виджет. Настройки
атомарно сохраняются в
`$XDG_CONFIG_HOME/dev.proteus.native/extension-preferences/mermaid-rust-render.json`
(при отсутствии XDG — `~/.config/dev.proteus.native/extension-preferences/…`).
Папка отделена от установленного пакета: сохранение не меняет его manifest
и не вызывает пересканирование/перезапуск расширения. Файл ограничен 4 КиБ.

После успешного изменения вызывается общий публичный
`surfaces.content.invalidate.v1`: клиент заново запрашивает content views
этого расширения во всех чатах, окнах и процессах. На очередном render
пакет проверяет метаданные файла и перечитывает его только после изменения;
невалидное внешнее изменение оставляет последние рабочие значения и
показывает ошибку на странице настроек. Фоновых таймеров/опроса нет.
Настройки входят в ключ ограниченного кеша; успешное сохранение и загрузка
новых настроек освобождают старые результаты. Неподтверждённый ввод не
сохраняется и не сбрасывает кеш, ошибочное значение не меняет диаграммы.
Другие структуры данных отдельных видов диаграмм ограничены размером
исходника; лимиты графа не являются универсальным лимитом сложности.
Жёсткого тайм-аута внутри синхронной библиотеки нет: безопасное прерывание
в середине компоновки её API не предоставляет.

Процесс использует тот же поддерживаемый кеш результатов, что Pele-адаптер:
максимум 8 записей и 4 МиБ ключей/деревьев для всех сессий, LRU-вытеснение,
удаление результата после закрытия последнего владеющего view. При смене
исходника/темы старое владение снимается. Хранятся только исходник+тема+SVG;
AST и layout освобождаются после рендера. Смена окна сохраняет view ID.

Это **не предел RSS процесса**. У upstream есть собственный глобальный
fontdb, кеш семейств шрифтов/метрик символов без публичного сброса. Первый
рендер может сканировать системные шрифты, а найденный шрифт сохраняется в
`$XDG_CACHE_HOME/mmdr/font-cache` (или `~/.cache/mmdr/font-cache`). Эти данные
могут переживать закрытие последнего view до завершения процесса пакета.
Эксперимент требует измерения холодного/повторного рендера и PSS/RSS перед
включением по умолчанию; цифры производительности upstream не являются
замером Proteus.

## Тема И Происхождение

`Content.context.theme` должен содержать цвета `foreground`, `background`,
`muted`, `border`, `accent`, `danger`, `surface`, `surface_alt` в формате
`#rrggbb` / `#rrggbbaa`; `font_family` берётся из клиента, при отсутствии
используется `sans-serif`. Палитра задаётся через публичный `Theme` upstream,
включая sequence, pie и git цвета; нет CSS-переменных и замены текста SVG.
Canvas SVG прозрачный: поверхность и углы внешнего кодового блока рисует
клиент. Узлы используют фоновый токен приложения, подписи рёбер — токен
поверхности; отдельного прямоугольного фона внутри рамки нет.

Оригинальная 0.3.1 не имеет общего радиуса узлов; эта возможность добавлена
описанным выше локальным патчем. `LayoutConfig` и синтаксис Mermaid при этом
не расширяются, подмена готового SVG не используется.

API: [разбор/компоновка/рендер](https://docs.rs/mermaid-rs-renderer/0.3.1/mermaid_rs_renderer/).
Архив crates.io и его проверенный SHA-256 записаны в `UPSTREAM.json`;
Cargo.lock общего экспериментального workspace фиксирует всю транзитивную
цепочку. `NOTICE-mermaid-rs-renderer` сохраняет полный MIT notice библиотеки;
`NOTICE-kurbo` — MIT notice используемой геометрической библиотеки;
адаптер — GPL-3.0-or-later, `LICENSE-GPL` ссылается на корень репозитория.

`UPSTREAM.json` также фиксирует SHA-256 локального патча и путь vendor.
Полный MIT-исходник импортируется автоматически, а воспроизводимость
проверяется без сборки:

```bash
python3 experiments/native-renderers/packages/mermaid-rust-render/update-vendor.py --check
```
