# Rust-рендереры: базовый набор и дальнейший перенос Pele

## Базовый набор

Используем существующие Rust-реализации и готовые библиотеки:

| Содержимое | Реализация | Проверяемая граница |
|---|---|---|
| Markdown: текст, таблицы, списки, tasklist, код | `packages/markdown-render` | GFM, примеры и исходники в кодовых блоках остаются буквальными |
| Формулы `$…$`, `$$…$$`, блоки `latex`/`tex` | `latex-render`, `latex-rust` | Математические формулы, включая кириллицу в `\text`; не TeX-документы |
| Базовые Mermaid-схемы | `mermaid-rust-render`, `mermaid-rs-renderer` | Проверяемый корпус: flowchart, sequence, class |
| Карточки, метрики, вкладки, композиции и SVG | `packages/json-render` | Существующий нативный каталог и его skill `visualize` |

Эти реализации уже есть; повторно писать Markdown/TeX/Mermaid parser не нужно.
Наши изменения скруглений, соединений стрелок и ветвления сохраняются вместе
с закреплённым upstream и патчами. Наличие типа в upstream parser ещё не
означает подтверждённую совместимость всей его грамматики.

Rust Mermaid и LaTeX пока остаются opt-in пакетами отдельного workspace;
это не изменение стандартного bundle. Текущая локальная portable-сборка
использует этот вариант, но повторяемая установка и promotion в стандартную
поставку требуют отдельной проверки. Старый Pele-адаптер сохраняется как
точка сравнения, без автоматического переключения с Rust на Node.

## Отложено: расширенные возможности Pele на Rust

Цель — постепенно закрывать нужные примеры из
[каталога Pele](https://pele.run/examples), сохраняя отсутствие JavaScript
в нативном варианте. Полный перенос Pele сейчас не выполняется. Перед
каждым этапом выбираем конкретные семейства и закрепляем ревизию источника;
live-каталог сайта может отличаться от поставляемого Pele 1.12.0.

- Составить постоянный синтетический корпус по семействам: что уже
  поддерживает готовая Rust-библиотека, что требует исправления, чего нет.
  Начать с обычных графиков/деревьев; Agentflow, Venn, Railroad, Swimlane,
  Wardley и другие дополнительные семейства включать отдельно по потребности.
- Переиспользовать существующие Rust parser/layout/геометрию. При переносе
  кода Pele сохранять MIT notice, происхождение и воспроизводимые патчи;
  не создавать общий parser/layout заново ради унификации названий.
- Для каждого семейства проверять результат в нативном окне: подписи,
  кириллицу, границы, стрелки, тему и ширину блока. Неподдерживаемый ввод
  должен сохранять копируемый исходник, без запуска Node в качестве fallback.
- Сравнивать cold/warm render, PSS/RSS, наблюдаемый пик, CPU и освобождение
  памяти после закрытия последнего view на одинаковых входах и ревизиях.
  Использовать существующий `bench.py`, не временные тесты вне проекта.
- Расширенные правила хранить вместе с renderer: короткое описание skill
  и отдельные справочники с примерами по семействам. На странице расширения
  показывать ссылку через общий `agent_instructions`. Связь с автоматическим
  обнаружением агентом — отдельный этап; сейчас skill подключается отдельно.
- Сохранить чтение существующих `json-render` и `svg` блоков. Карточки,
  метрики и локально переключаемые вкладки не заменяются статической схемой.

Готовность к стандартной поставке: поддерживаемые семейства документированы,
корпус и нативные проверки проходят, стоимость измерена, закрытые view не
удерживают свои исходники/деревья. Новые типы не объявляются поддержанными
только по наличию демонстрации на сайте Pele.
