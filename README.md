# Расширения приложения Proteus

Поставляемый по умолчанию набор расширений клиента. Автор в манифестах —
`Proteus Project`. Репозиторий — `Proteus-desktop-extensions`; приложение
[Proteus-desktop](https://github.com/Proteus-harness/Proteus-desktop) подключает
закреплённую ревизию этого набора при сборке поставки.

Набор входит в experimental-поставку `0.1.0-alpha.3`; версия поставки и
`protocol: 3` манифестов независимы. Точная ревизия записывается в манифест
релиза Desktop. GitHub Actions этого репозитория запускаются вручную;
обычные push и PR не запускают проверки.

Приложение включает эти пакеты в поставку и включает их по умолчанию. Код
расширений исполняется отдельными процессами, общается через публичный
[протокол клиента](PROTOCOL.md) и HTTP API app-server. Изменение программы
или установка обновлённого ZIP не требуют сборки приложения. Новому виду
нативного виджета нужна поддержка в клиенте; терминальный эмулятор, редактор,
дерево и граф остаются общими виджетами, доступными любому расширению.

| Пакет | Возможности |
|---|---|
| `quota` | Лимиты модели, недельный остаток, все окна и кредиты |
| `context` | Заполнение окна контекста: кольцо на панели, по нажатию карта категорий, кэш провайдера, история и компакция |
| `plan` | Последний план и выполненные шаги |
| `mode` | Выбор режима разрешений |
| `model` | Выбор модели, глубины рассуждений и дополнительных select-настроек сервера |
| `files` | Панель проекта в духе Zed: дерево с цветами git, свёрткой папок и контекстным меню, просмотр файла и diff |
| `git` | Панель git: индекс, коммит, отмена изменений, ветки и история |
| `terminal` | Вкладки терминала в рабочей папке |
| `usage` | Расход и оценка стоимости по запросам |
| `analysis` | Ходы и шаги сохранённых сессий |

Пакеты написаны на Rust: каждый — отдельный бинарник из общего cargo
workspace, `sdk` — крейт `proteus-extension` (цикл протокола, HTTP API,
построители виджетов). `packages/<id>` содержит манифест и исходники; манифест
запускает `bin/<id>`. `shelved/` хранит отложенные пакеты, которые не входят в
поставку. Упаковщик собирает release-бинарники и кладёт их с файлом лицензии пакета в каждый
пакет, поэтому готовые пакеты самостоятельны. Для упаковщика и тестов протокола
нужен Python 3 со стандартной библиотекой.

```bash
python3 package.py                         # dist/<id>.zip
python3 package.py --output /tmp/packages
python3 package.py --bundle /tmp/extensions # новая папка для portable
python3 package.py --bundle /tmp/extensions --no-build # готовые release-бинарники без Cargo
python3 package.py --dev                   # бинарники в packages/<id>/bin для запуска из исходников
cargo test --workspace
python3 -m unittest discover -s tests -p 'test_*.py'
```

Тесты запускают реальные процессы и локальный HTTP-сервер с синтетическими
данными. `tests/wire.py --wire` отдаёт реальные ответы всех пакетов для
проверки парсером Rust-клиента; `--packages <папка>` проверяет готовую поставку.

Для чтения полной структурированной истории SDK предоставляет
`Host::conversation()` и `conversation_for(Some(session_dir))` через общий
`GET /conversation`. `ConversationView/v1` сохраняет канонические блоки,
идентификаторы, metadata и источник; чтение сохранённого чата не активирует его.
Граница текущего снимка и пример без UI описаны в
[протоколе](PROTOCOL.md#чтение-структурированной-истории).

В общей рабочей раскладке `Proteus-desktop` читает соседний
`Proteus-desktop-extensions/packages`.
Для отдельного checkout клиента `scripts/run.py` подготавливает набор и путь.
Portable читает `share/extensions` рядом с `bin`; `PROTEUS_EXTENSIONS_DIR`
позволяет указать другой набор. Пользовательская установка в
`~/.config/dev.proteus.native/extensions/<id>` перекрывает поставляемую с тем
же id. ZIP ставится в настройках «Клиент → Расширения». Обновление атомарно:
плохой архив оставляет прежний пакет. Порядок, включение и размещение значков
при обновлении сохраняются. Удаление пользовательской версии выключает
восстановленный поставляемый пакет; включить его можно тем же переключателем.

## Лицензия

Как в [Zed](https://github.com/zed-industries/zed), лицензия задана у каждого
крейта: поле `license` в Cargo.toml и ссылка на `LICENSE-GPL` или
`LICENSE-APACHE` в корне. Пакеты — GPL-3.0-or-later (содержат код,
заимствованный из Zed); SDK `proteus-extension` — Apache-2.0, поэтому своё
расширение на нём можно выпускать под любой лицензией. В ZIP каждого пакета
кладётся его файл лицензии.
