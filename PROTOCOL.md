# Протокол расширений клиента, версия 3

Манифест `extension.json` и JSON Lines через stdin/stdout. Программа запускается
в папке пакета. stdout содержит только JSON; диагностика идёт в stderr.
Все поставляемые пакеты используют этот же контракт, без отдельных builtin
регистраций. Версия 1 отвергается явно: производитель и клиент обновляются вместе.

```json
{
  "protocol": 3,
  "id": "example",
  "title": "Пример",
  "author": "Proteus Project",
  "description": "Описание",
  "icon": "chart-column",
  "command": ["bin/example"],
  "session_events": true,
  "surfaces": {
    "page": {},
    "panel": {"title": "Пример"},
    "document": {"label": "{filename}"},
    "badge": {"place": "header_end", "narrow": true},
    "popup": {"width": 280, "height": 420}
  }
}
```

`id` совпадает с папкой (латинские строчные буквы, цифры, дефис; до 48 символов).
Нужна хотя бы одна поверхность; popup требует badge. Страница появляется в
настройках расширений. `document.label` поддерживает `{filename}` и
`{argument}`; `command` — программа и аргументы; путь со `/` (например,
`bin/example`) считается относительно папки пакета, иначе программа ищется в
`PATH`. `document.command` объявляет адрес команды, например
`terminal.new`. Приложение создаёт такой документ, не зная id расширения.
`popup.escape_action` перенаправляет Esc действием вместо немедленного закрытия.

Места значка: `composer_start`, `composer_end`, `header_start`, `header_end`,
`rail_start`, `rail_end`, `hidden`. Для rail требуется `narrow: true`; узкий
значок допускает icon (в том числе числовой счётчик) или ring. Текстовые
значки допускаются в остальных местах. Ширина popup — 100–1200 пикселей;
`height` — наибольшая высота до прокрутки, 120–1000 (по умолчанию 420).

## Расширяемые данные и возможности

`protocol: 3` задаёт обязательную форму сообщений. `hello.features` содержит
необязательные возможности клиента; сейчас — `session.settings.v1` и
`widgets.controls.v1` (`checkbox`, `menu`, `confirm`, `prompt`, многострочный
`input`, цвета `#rrggbb`, иконки Lucide, поля строк дерева, `lanes`, `list`,
`spacer`, `bar`, `panel_editor`, `empty`, `icon`, split-кнопки).
`extension.json.required_features` перечисляет возможности, без которых пакет
не работает: клиент проверяет их до запуска и показывает явную ошибку.
Необязательную возможность пакет проверяет перед использованием. Feature не
меняет права процесса и не разрешает новые host callbacks.

В корне `extension.json` разрешён необязательный объект `_meta` с ключами
`namespace/name`, например `org.example/build`. Неизвестные записи сохраняются
как описательные данные; поведение и обязательные поля остаются типизированными.
Произвольные дополнительные поля вне `_meta` не допускаются.

`config.session_settings` — полное актуальное описание доступных настроек:

```json
{"id":"reasoning_effort","name":"Reasoning","category":"thought_level",
 "control":{"type":"select","value":"effort:high","options":[
   {"value":"_default","name":"Default","description":null},
   {"value":"effort:high","name":"high","description":null}]}}
```

`id` и `value` непрозрачны для общего клиента; `category` — только подсказка
для размещения. Неизвестный тип контрола не показывают, его данные сохраняются
при передаче config процессу. Известный select остаётся строгим. Сервер
проверяет id/value и возвращает полный config после изменения, включая
зависимые настройки модели. HTTP-эквивалент — `POST /session/setting` с
`{id, session_dir, setting:{id,value}}`. `_default` у рассуждений снимает явный
effort, чтобы его выбрал провайдер. Новому select не нужна новая версия
нативного enum; новый вид нативного контрола требует поддержки рендерера.

## Клиент → процесс

- `hello`: `protocol: 3`, `features`, `workspace`, `server: {origin, token}`. Токен нужен
  для HTTP app-server, передаётся только процессу. Не записывайте его в логи.
- `render`: `view`, `surface`, необязательные `argument`, `session_dir`.
  `surface`: `page`, `panel`, `document`, `badge`, `popup`, `content`. Для
  `content` обязателен типизированный `content: {language, source}`. Непрозрачный `view`
  нужно возвращать без изменений.
- `close`: `view`. Поверхность закрыта; её таймеры можно остановить. Процесс
  сохраняется до закрытия workspace, выключения или обновления пакета.
- `action`: `view`, `action`, необязательное `value`, монотонный `sequence`.
- `event`: `event` (`session_opened`, `run_settled`, `navigation_changed`),
  необязательный `session_dir`, `document` — аргумент активного документа
  этого расширения. Отсутствие сессии/документа означает null.
- При `session_events: true`: `session_snapshot` с `session_dir`, `state`,
  `entries`; затем `session_update` с `session_dir`, `update`. Снимок повторяется
  при смене активного чата. Обновление `type: state` заменяет `state`;
  `type: entries` заменяет диапазон `start..start+removed` на `entries`.
  Передаются состояние/конфигурация и метаданные ленты (роль, tool, subagent),
  без текста ответов и повторной пересылки истории при каждом текстовом delta.
- `command_result`: `id`, `session_dir`, `config` или `error` для `set_session`.

`state` содержит `connected`, `config`, `context`, `execution`, `pending`,
`activity`. DTO конфигурации и событий совпадают с app-server. Точные структуры
в Proteus-desktop: `src/declarative/{protocol,session,manifest}.rs`.

## Процесс → клиент

- `view`: `view`, `session_dir` (может быть null), `sequence` (последний обработанный
  action, исходно 0), `root` — полное дерево виджетов. Ответ другой активной
  сессии или более старого action не применяется. Необязательное `keys` —
  объект `{ "ctrl-f": "search-focus", "escape": "escape" }`: сочетание вызывает
  action этой поверхности. Обычные текстовые клавиши в поле ввода сохраняются.
  Необязательный `title` (`documents.title.v1`) задаёт видимую подпись document
  отдельно от стабильного `argument`: SDK `show_with_title`. Применяется
  только вместе с актуальным `sequence`, поэтому устаревший ответ не меняет
  название вкладки.
- `badge`: `view`, `session_dir`, `title`, `lines`, `hidden` (исходно false),
  `face`: `{type: "icon", tone, count?}`, `{type: "text", text, icon?, caret?, tone}`
  или `{type: "ring", percent, tone}`. Процент — конечное число 0–100.
- `open_document`: `argument`, `preview` (исходно false), `focus` (исходно true).
  Открывает документ своего расширения.
- `set_session`: `id`, `session_dir`, `setting: {id, value}` (`id` — строка, тип `value` задаёт control).
  Требует `session.settings.v1` в `hello.features`. Допустимые id и значения
  берутся из `config.session_settings`, а не из enum клиента. Команды выполняются по очереди, только для
  активной сессии; результат коррелируется через id. Ошибка видна в чате и
  возвращается процессу. Запросы/изменения остальных данных — через HTTP API.
- `close_popup`: закрыть выбор и вернуть прежний фокус.
- `clipboard`: `text`.
- `focus`: `view`, `control` — id input/tree/code/terminal этой поверхности;
  null возвращает фокус в активный чат. Новая панель с деревом передаёт ему
  фокус контейнера, чтобы стрелки сразу работали.

## Виджеты

Закрытая схема: неизвестное поле даёт ошибку поверхности, неизвестный тип узла
рисуется заглушкой «требует более новой версии Proteus» (остальной вид работает).
Пакеты с контролами из `widgets.controls.v1` указывают её в `required_features`. Доступны
`stack`, `fill`, `split`, `card`, `text`, `metric`, `progress`, `table`, `bar_chart`,
`tabs`, `list`, `button`, `badge`, `divider`, `spacer`, `input`, `checkbox`, `menu`,
`code`, `terminal`, `tree`, `lanes`, `graph`, `select`, `picker`, `steps`, `cells`,
`bar`, `panel_editor`, `empty`, `loading`, `icon`, `diff`, `svg`.
Тон — `default`, `muted`, `accent`, `success`, `warning`, `danger` или цвет
`#rrggbb`. Иконки (`icon` в манифесте, кнопках, меню и строках дерева) — имена
файлов Lucide: `folder-tree`, `git-branch`, `refresh-cw`, `rotate-ccw`,
`chevron-left`, `copy`… Неизвестное имя — ошибка.
`text.single_line: true` — однострочная подпись или превью, которое плавно
исчезает у края доступной ширины; исходный текст передавайте без многоточия.
По умолчанию `text` переносится как обычный многострочный текст.
`sortable` (`widgets.sortable.v1`) — `id`, `action`, `items`:
`[{id, label, children}]`. У item постоянный уникальный непустой `id`,
`label` задаёт подпись native ghost, `children` — обычные публичные примитивы.
Клиент держит жест удержания всей строки, анимацию соседей, полный drag-preview,
отмену и фокус; вложенные кнопки, поля и переключатели сохраняют свои действия.
При фокусе самой строки Ctrl+Shift+↑/↓ меняет порядок тем же action; поля
внутри строки сохраняют свои клавиши. Подтверждённый drop передаёт `{id, before}` (`before: null` — в конец), порядок
меняет пакет и возвращает авторитетный `view`. До этого ответа native сохраняет
предпросмотр порядка. SDK: `sortable(id, items, action)` и
`sortable_item(id, label, children)`. Extensions и Hooks клиента используют тот
же native renderer. Установка пакета, использующего эту возможность, не
требует пересборки host; capability проверяется при загрузке манифеста.

`picker` (`widgets.picker.v1`) — общий поиск и выбор: `id`, `action`,
`options: [{label, value, selected}]`, необязательные `placeholder` и `empty`.
Значения уникальны, выбрано не больше одного варианта; пустой список допустим.
Клиент фильтрует слова без учёта регистра, виртуализирует строки, сохраняет
выделение при обновлении, прокручивает к выбранному, обрабатывает ↑/↓,
PageUp/PageDown и Enter. Esc сначала очищает поиск, затем закрывает popup.
Поиск, фокус, анимацию и строки не нужно собирать в процессе. SDK:
`picker(id, &options, &selected, action)`. Model и Branch используют тот же
контрол; прежний отдельный `choice` не является частью чернового протокола.
`loading` (`widgets.status.v1`) — `text`: общий отложенный спиннер и подпись.
Для отсутствия данных служит `empty`; ошибка не сопровождается спиннером
ожидания. Клиент сам показывает это состояние, пока ждёт первый `view`.

`cells` — квадратная сетка с легендой: `columns` (1..100, по умолчанию 20) и
`segments` — `{label, cells, tone?, color?, value?, detail?}`, где `cells` —
число клеток сегмента (всего не больше 2000), `color` — `#rrggbb` вместо тона,
`value`/`detail` выводятся в легенде и подсказке. Распределение клеток
считает процесс.

`diff` требует `widgets.diff.v1` в `required_features` и содержит `id`,
`patch` — исходный unified diff Git (несколько файлов допустимы) или полный
apply_patch, `files?` — дополнительные `{path, status?, message?}` для
файлов без текстового patch, и `height?` — положительную высоту. Без `height`
виджет занимает оставшуюся высоту `fill`, как `code`. `status` использует
значения git API (`added`, `untracked`, `modified`, `deleted`, `renamed`,
`conflict`); неизвестное/пустое значение рисуется обычной иконкой файла.
Метаданные объединяются с patch по пути; файл без patch остаётся карточкой
с `message`. Для уже разобранного текстового файла сообщение не добавляется.
Клиент сам считает строки, сохраняет свёрнутые файлы и выбор split/unified,
переключается на unified при узкой ширине и виртуализирует строки.
Патч без диапазона `@@ -old +new @@` не получает выдуманных номеров строк.
SDK: `diff(id, patch).with("files", files)`.

```json
{"type":"diff","id":"changes","patch":"diff --git a/a.rs b/a.rs\n--- a/a.rs\n+++ b/a.rs\n@@ -1 +1 @@\n-old\n+new\n","files":[{"path":"image.png","status":"added","message":"Двоичный файл"}]}
```

У интерактивных контролов постоянный `id` и `action`; сохраняйте их тип и
назначение при перерисовке. `input` передаёт строку при каждом изменении;
`lines` (1..40, по умолчанию 1) больше 1 делает многострочное поле
постоянной высоты в `lines` строк с прокруткой внутри; `placeholder` обновляется
при каждой перерисовке; `flush: true` — поле без рамки и фона на всю ширину
(редактор коммита в `panel_editor`); `mono: true` — моноширинный шрифт кода;
`search: true` (`widgets.search.v1`) — компактный поиск в строке header/toolbar:
пустое неактивное поле занимает только кнопку Search, явный Ctrl+F раскрывает
и фокусирует поле без отдельной строки; ввод сохраняется при обновлении данных.
Первый Esc очищает запрос, следующий возвращает фокус к содержимому и сворачивает
пустое поле. Обычный начальный фокус поверхности не раскрывает поиск.
Только `lines: 1`; SDK `ui::search` строит такой input.
`submit` — action, который получает текст по Enter (в многострочном поле —
Ctrl+Enter). `checkbox` — `label`, `checked`, `action`, `value?`; шлёт
`{checked, value}` с новым состоянием. `select`/`picker` —
выбранное JSON value; `steps` — индекс варианта; `graph` — id узла;
`tree` и `lanes` — `{id, event}` (`select`, `preview`, `open`, `expand`,
`collapse`, `check`).
`button` — `label`, `action`, `value?`, `variant` (`default`, `primary`,
`ghost`, `danger`), `icon?`, `selected` (активная кнопка
группы, например текущая вкладка), `hint?` (подсказка при наведении, видна и у
выключенной кнопки; для кнопки только с иконкой `label` может быть пустым),
`disabled` (исходно false), `confirm?` или `prompt?` и `menu` — пункты меню:
непустой `menu` превращает кнопку в split-кнопку (основная часть шлёт `action`,
часть со стрелкой открывает пункты). SDK-помощники: `segments` строит ряд
вкладок, `split_button` — split-кнопку.
`confirm` — `{title, message?, ok?, danger?}`: перед отправкой action клиент
спрашивает пользователя. `prompt` — `{title, placeholder?, value?, ok?, stem?}`:
клиент открывает диалог с однострочным полем (исходный текст `value` выделен;
`stem: true` выделяет только часть до последней точки, как имя файла без
расширения) и по OK или Enter шлёт action со значением
`{"value": <value кнопки или пункта>, "text": <введённый текст>}`. `confirm` и
`prompt` вместе не допускаются. `menu` — кнопка (`label?`, `icon?` — без `label`
по умолчанию `ellipsis`, `hint?`) с выпадающим списком `items`: `{label, action, value?, icon?,
danger?, confirm?, prompt?, separated?, checked?, selected?, disabled?, header?}`
(`separated` рисует разделитель над пунктом, `checked: true|false` — пункт-
переключатель с галочкой, `selected: true|false` (`widgets.selection.v1`, исходно false) —
эксклюзивный выбор с общей заливкой выбранной строки, без галочки; `selected: true`
и `checked` вместе не допускаются. `disabled` — серый пункт, `header: true` — заголовок
раздела, который нельзя выбрать; только у заголовка `action` может отсутствовать).
`spacer` — пустое место, которое в ряду `stack` отодвигает следующие элементы
к правому краю.
`bar` — компактная полоса у края панели, как подвалы git-панели Zed:
`children` и `border` (исходно true — линия сверху и отступ 6 px; false —
без линии, отступы 8×6 px, как полоса ветки под списком). Элементы до
`spacer` стоят в начале и сжимаются при нехватке места (подпись кнопки или
меню обрезается, меню открывается вверх от левого края), остальные — в конце.
Кнопки и меню в полосе компактные (мелкий текст, 20 px). `panel_editor` —
область редактора внизу панели (`children`): линия сверху и фон редактора за
`input` с `flush: true` и `bar` под ним; линия над этой полосой появляется,
когда текст заполнил все `lines` строк. `empty` — `text`: приглушённая строка
по центру оставшегося места (пустой список). `icon` — `name` (Lucide) и
`tone` (исходно `muted`): маленькая иконка, например ветки перед меню веток.
`tree` — `id`, `rows`, `action`, `indent` (px на уровень, 0..64, по умолчанию 16),
`chevrons` (исходно true; false — ветка показывает только иконку папки, без
стрелки, как панель проекта Zed), `guides` (исходно true; тонкие линии уровней,
линия ближайшей раскрытой ветки курсора ярче).
Строка дерева: `id`, `label`, `detail?` (приглушённый текст сразу после имени;
не помещаясь, обрезается с начала — например, папка файла), `depth`,
`expanded` (null — лист), `tone`, `selected`, `icon?` (по умолчанию папка/файл),
`icon_tone?`, `checked?` (`true`, `false` или `"mixed"` — частично, рисуется
чёрточкой; чекбокс справа в строке, клик по нему шлёт только `check` и не
выбирает строку), `strike` (зачёркнуто), `menu` — пункты контекстного меню по
правому клику, `kind` (`item` по умолчанию или `header` — заголовок раздела:
стрелка по `expanded`, мелкий приглушённый текст, клик шлёт `expand`/`collapse`,
клавиатура его пропускает), `count?` (число в рамке справа), `stats?` —
`{added, deleted}` (неотрицательные целые, справа `+N −M` зелёным/красным) и
`hint?` (подсказка при наведении, например полный путь).
Дерево поддерживает стрелки, Home/End, PageUp/PageDown, Enter и пробел.
←/→ шлют `collapse`/`expand`, но на листе или свёрнутой ветке ← переводит
курсор к родителю, а на раскрытой ветке → — к первому потомку (с `preview`).
Клик шлёт `select`, двойной клик — `open`; двойной клик по ветке (`expanded`
не null) не шлёт `open`: первый клик уже отправил `select`.
`lanes` — виртуализированный список с колонкой линий (история коммитов):
`id`, `action`, `columns`, `rows`; требуется `widgets.lanes.v2`. Колонки —
`{label, weight, kind?}` с положительными весами; ровно одна `kind: graph`,
остальные `text` (по умолчанию), `person` или `mono`. Нативные заголовки
масштабируют колонки вместе со строками, разделители перетаскиваются, правый
клик по заголовку скрывает/показывает текстовые колонки. Строка: `id`, `lane` (дорожка точки строки), `color`,
`up` и `down` — списки `{from, to, color}` (`up` ведёт линию от дорожки `from`
у верхнего края строки к дорожке `to` в её середине, `down` — от `from` в
середине к `to` у нижнего края; при `from == to` линия прямая, иначе изгиб;
линия, касающаяся точки, входит в её кольцо сбоку), `label`, `refs?` —
`[{label, tone?}]` (метки в колонке графа), `cells` — строки по числу колонок
(пустая строка для графа), `selected`, `menu` (правый клик),
`hint?`. Дорожки — меньше 64, цвета — индексы 0..7 палитры клиента. Клик шлёт
`select`, двойной клик и Enter — `open`, ↑/↓, Home/End, PageUp/PageDown
двигают выбор и шлют `select`. SDK: `lanes`, `lane_row`, `lane_segment`.
`list` — виртуализированный список двухстрочных строк, как история коммитов
в панели Zed: `id`, `action`, `rows`. Строка: `id`, `label` (первая строка),
`chips?` — строки-метки после неё (видны первые три, остальные — чип «+k» с
подсказкой), `mark?` — иконка Lucide в рамке в конце первой строки (например,
`arrow-up` у неотправленного коммита), `avatar` (кружок с человеком в начале
второй строки), `meta?` — части второй строки, мелким приглушённым текстом
через «•» (пустые пропускаются, первая обрезается при нехватке места),
`hint?` и `hint_detail?` — подсказка при наведении и её приглушённая вторая
строка, `menu` (правый клик). Клик шлёт `{id, event: "preview"}`, двойной клик
и Enter — `{id, event: "open"}`;
↑/↓, Home/End, PageUp/PageDown только двигают курсор (рамка курсора видна после
клавиатуры). SDK: `list`, `list_row`. Для открытия документов из строк используйте
`Host::browse_document(argument, event)`: выбор заменяет общую временную вкладку,
`open` закрепляет документ и переводит в него фокус. Это одинаково для файлов и коммитов. `list` и `lanes` делят одну реализацию
списка: курсор, клавиатуру, фокус и меню.
`disclosure` (`widgets.disclosure.v1`) — `{id, label, open?, children}`: нативный
шеврон и общая анимация раскрытия. `open` задаёт начальное состояние (true
по умолчанию), дальнейшее состояние хранит клиент по id независимо для каждого
документа. `person` (`widgets.person.v1`) — `{name, detail}`: заголовок с локальным
аватаром из инициалов и подписью, без сетевого запроса по имени или email.
`code` — редактор только для чтения, `language`, необязательная `height`;
без height занимает оставшееся место. `wrap: true` переносит длинные строки и
скрывает номера строк (для текста и логов); задаётся при создании редактора с
данным `id`. `terminal` — PTY с `cwd`.
`fill.children` отдаёт остаток высоты `tree`, `lanes`, `code` без `height`,
`terminal`, `split`, `graph`, вложенному `fill` и `tabs` (тело выбранной вкладки
тогда тоже раскладывается как `fill`); остальные дочерние элементы сохраняют
естественную высоту, так что шапка над списком и подвал под ним закреплены.
`fill.children` также отдаёт остаток высоты `list` и `empty`.
`stack` располагает элементы по содержимому. `tabs` — `tabs: [{label,
count?, children}]` и `action?`, который получает индекс вкладки при
переключении; вкладки равной ширины через тонкий разделитель, неактивные
приглушены, `count` больше 0 рисуется мелкой приглушённой меткой «(N)» после
названия, как в Zed. `split` — ряд колонок на всю
высоту: `children` и `widths` (ширина в px или `null` для резиновой колонки);
дочерние `fill`, `tree`, `lanes` и `terminal` растягиваются по колонке, остальное прокручивается внутри неё.
Контролы, исчезнувшие из дерева,
освобождаются вместе с ресурсами (включая PTY).

Полные поля и проверки — [схема клиента](https://github.com/Proteus-harness/Proteus-desktop/tree/main/src/declarative),
живые примеры — `packages`. Rust SDK (`sdk`, крейт `proteus-extension`) обрабатывает жизненный цикл, последовательности,
обновления сессии и корреляцию команд. Таймеры SDK работают только при открытых
поверхностях. Закрытие приложения останавливает группу процессов расширения.

## Контент ответа в чате

`surfaces.content.v1` — общая поверхность для завершённых fenced-блоков
ответа ассистента. Пакет сам объявляет языки; в клиенте нет каталога имён
рендереров и специальных веток по имени расширения:

```json
{"surfaces":{"content":{"languages":["my-figure","my-report"]}},
 "required_features":["surfaces.content.v1"]}
```

Идентификаторы языков непустые, уникальные, в нижнем регистре; допустимы
латинские буквы, цифры, `_`, `+`, `.`, `-`. Если один язык объявили несколько
включённых пакетов, используется первый в пользовательском порядке Extensions.
Изменение состава/порядка включённых пакетов применяется и к уже открытой ленте.
Обновление того же пакета перезапускает его процессы, сохраняя оболочки блоков.

```json
{"type":"render","surface":"content","view":"content:opaque-block-id",
 "argument":"opaque-block-id","session_dir":"/session/original-chat",
 "content":{"language":"my-figure","source":"original closed fence contents\n"}}
```

`content` — типизированные исходные данные, отдельно от адреса `view`.
В SDK это `Surface::Content` и `host.content(view) -> Option<&Content>`
с полями `language`/`source`. Возвращайте обычный `host.show(view, tree)` с
публичными Node. Для нового языка/каталога не требуется пересборка клиента,
если достаточно уже имеющихся нативных примитивов. Действия виджетов
передаются процессу только после явного ввода пользователя. Сам факт появления
блока в ответе не отправляет сообщение агенту и не вызывает инструмент.

Рендерятся только закрытые блоки верхнего уровня. Обычный код, вложенные
fence в списках/цитатах, неизвестный язык и незакрытый streaming-блок остаются
обычным markdown. Источник закрытого блока передаётся один раз при его появлении;
дальнейшие delta текста после него не повторяют render. Неизменившийся блок
сохраняет отдельный view, Tabs/поля/раскрытия и состояние source toggle при
виртуализации, прокрутке и переключении вкладки. Изменившийся источник получает
новый адрес; запоздалый ответ на прежний источник не применяется к новому.

Оболочка клиента даёт общее копирование полного `source` и переключение
preview/исходник. Пока процесс загружается, при выключении/удалении пакета,
пустом/неизвестном дереве, ошибке протокола или рендера остаётся исходный код.
Изменение высоты блока использует общий scroll anchor чата. Контент имеет
естественную высоту, а не высоту окна документа.

```json
{"type":"content_error","view":"content:opaque-block-id",
 "session_dir":"/session/original-chat","sequence":0,"error":"Unsupported source"}
```

Ошибка относится к конкретному view; `sequence` проверяется как у `view`.
SDK автоматически отправляет её при ошибке/панике `render`/`action` content
поверхности. Прежнее удачное дерево не подставляется вместо ошибочного
источника. `close` удаляет payload и сохранённый ответ из SDK. Chat content
процессы привязаны к исходному чату, а не к активной вкладке; последняя
поверхность освобождает процесс при удалении блоков/закрытии чата. Пользовательские
page/panel/document/badge процессы по-прежнему живут до закрытия workspace.

### Цветной SVG

`widgets.svg.v1` добавляет общий Node и SDK `ui::svg(source, width, height)`:

```json
{"type":"svg","source":"<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 20 20\"><rect width=\"20\" height=\"20\" fill=\"#4c9aff\"/></svg>",
 "width":640,"height":360}
```

`width`/`height` — область в логических пикселях, конечные числа 1…4096.
Пропорции исходного SVG сохраняются; изображение вписывается в область.
Цвета, градиенты, пути и текст рисуются нативно через GPUI/resvg, без WebView.
Результат кешируется по source, размерам и DPI/масштабу интерфейса; прокрутка
не запускает новый разбор. Источник ограничен 1 МиБ, XML должен иметь корень
`svg`; разрешены локальные `#fragment` references. Внешние href (включая файлы),
HTML `foreignObject` и `script` не загружаются. Ошибка native SVG parser/raster
также возвращает content оболочку к исходнику, даже если XML прошёл схему.
